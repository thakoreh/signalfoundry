# Hosted ledger prerequisites — internal and incomplete

This is an offline-tested foundation, **not hosted outreach parity or a live integration**. The existing SaaS REST adapter still denies every outreach route. No client calls the new functions. Nothing was deployed, connected, sent or paid for. Local SQLite and its working journey are unchanged.

## Implemented contract

`frontend/convex/outreachLedger.ts` exports internal queries and mutations only, through the existing convex-helpers verified-Clerk wrappers. Reads require an active tenant identity; mutations require the organization admin role. Every invocation also carries `expectedOrgId`, an intent comparison against verified identity, never a scope-granting argument. Resource ownership is checked before returning data or replaying an operation.

- `start`: one to five distinct IDs from a completed/partial owned saved search; no client-supplied account contents. Demo records are refused. Named-style email ranks above common shared inboxes; publication remains unverified. A contact basis is never inferred. Repeated starts reuse the saved record.
- `get`/bounded `list`: current saved work. GET does not change approvals, generate, reserve, send, or log contact.
- `edit`/`saveBasis`: revision-checked manual text and public-source/role/notice/US-Canada attestation. Sender name, company, address and reachable contact must exist in the current saved profile; the exact local footer must end the saved message. Optional sender fields were added compatibly to the existing profile validator; old profiles still parse and need explicit repair before approval.
- `approve`: immutable exact recipient/subject/body/basis snapshot bound to current revision, latest received context, saved profile version and company review version. All edits and stops invalidate the live approval reference. Restoring earlier profile values cannot restore an earlier version's approval.
- `checkManualAction`: read-only fresh current approval identity check; it neither opens an email app nor records sending.
- `reportSent`: explicit user report bound to the actual approval ID. Changed actual text is stored separately from the untouched approval record. An idempotent replay returns current safety state rather than restoring an old decision.
- `pasteReply`/`classifyReply`: every specified manual classification, immutable original received text, safe missing-date review, explicit offset/IANA validation including both Toronto folds, permanent cold-sequence stop after any inbound. Correcting a classification does not edit the original received record. Obvious opt-out/source-question wording fails closed. These functions do not detect mail or claim a provider-confirmed reply.
- `pause`: explicit founder decision acknowledges the current company review version and clears approval. Any inbound invalidates sibling company approvals. One cold owner is checked transactionally. Explicit resume plus a **new** approval after a sibling reply is allowed by OWNER_CONTRACT, without clearing sticky company/email suppression or bounce invalidity.

Additive indexed Convex tables retain current threads, company safety versions, immutable approval/message records, durable suppressions, request fingerprints and bounded tenant counters. No new dependency/service/cache/queue was added. Limits: 100 threads/tenant, 50 messages/thread, 10,000 new operations/tenant; replay stays available at the operation cap. All reads use ownership checks/indexes and bounded takes. Convex mutations perform the decision, counters and records in one transaction; local mocked races test the intended contract, not the deployed OCC service.

## Gates, rollback and remaining work

`SIGNALFOUNDRY_HOSTED_OUTREACH_PERSISTENCE_ENABLED` must equal `true` to invoke these internal prerequisites; it defaults off. This flag is **not** an adapter enablement switch and must stay unset for the owner until explicit deployment/connection authority. Tests set it only in their isolated runtime. Turning it off retains all records and denies reads/mutations; it cannot undo a manual external action. Roll back with reviewed forward/revert commits; retain newer suppression, immutable sent and audit records. Do not drop tables or restore an old database to clear stops.

Still unbuilt here: hosted referrals, bounded followup scheduling, meetings/outcome audit, Next up/funnel projections, hosted export/closure/retention and adapter/UI parity. To avoid a bypass before the bounded hosted sequence exists, a reported cold initial send cannot be followed by another hosted cold initial approval. Manual answers require the latest eligible same-recipient interested/question context. No reply AI, monetary admission, OAuth, transport, calendar, scheduler or mailbox operations are connected to these functions. Shared monetary authority across hosted and local remains unresolved; every hosted paid dispatch stays closed.

No `convex dev`, code push, live account lookup, real JWT, inbox or deployed database was used. `_generated/api.d.ts` received additive offline module references for local type safety; no claim of remote codegen/push is made. Full hosted parity and actual authenticated provider testing must pass before changing the closed adapter. Full Chrome14-step acceptance remains separately pending, as does physical-phone/screen-reader testing.
