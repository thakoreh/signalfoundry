# Local monetary admission — built offline, live operation blocked

The US$25 monthly ceiling includes historical DeepSeek usage. Its historical amount is **unknown**. No policy, source price, balance, zero usage, free credits or spending authorization is seeded. No Ads allocation exists. A configured provider key does not authorize dispatch.

`app/cost_admission.py` uses the same authoritative SQLite file as the local app. Atomic global plus tenant admission holds integer micro-USD before each HTTP dispatch. Search, Hunter lookup/verifier and initial draft transports carry explicit server-selected context. Cached drafts do not dispatch. The supported server catalog is empty until an operator supplies accepted prices/model/billing bounds, source/version and reconciled history. No actual current price is asserted by this implementation; test rates are fictional.

One global paid call may be in flight. Both pending and uncertain rows stop every further paid call, across tenants and months. This deliberately conservative small-trial bound also prevents a failed settlement write from permitting more spending. A timeout, unreadable response, absent/inconsistent/over-bound usage, interruption or failed settlement never refunds its hold. App startup marks abandoned dispatches uncertain. A later authentic receipt can settle its matching attempt once. Conflicting receipts stop work. Actual reconciled over-bound cost is retained and remains a stop, never clamped to the quote. Read-only status reports new-ledger exposure separately from whether history is known.

Each attempt has an immutable tenant/logical-operation/input fingerprint, price snapshot and UTC period. Retries reuse business results or fail closed; new input under the same attempt cannot dispatch again. Draft usage settles before content validation, so a rejected model answer can still consume allowance. Token admission uses a pessimistic encoded-byte bound plus framing and the highest accepted uncached rates, not a guessed four-characters/token ratio; cache discounts are not assumed. The quote is a ceiling calculated from the accepted policy, not a provider invoice. Real invoice reconciliation remains an operator step.

The local global scope covers every tenant/process using **this one database**, not independent copies or external use of the same provider account. Separate hosted/stateless workers have no authoritative context and are denied at transport. Live Jev remains denied; deterministic rules and network-free MockTransport tests remain. Hosted paid parity is not implemented and must stay disabled. Do not give real keys to unguarded old deployments or fixtures.

## Operator steps, after separate owner authorization

No command below buys credit, connects accounts, makes a paid call or sends email. Do not run it against the owner's data as a test. Back up the explicit database first. Keep private billing statements/policy files outside Git; never put keys or prospect data in them.

1. Inspect local `GET /api/cost/status`, or `python scripts/cost_control.py --db ABSOLUTE_DATABASE_PATH status`. Unknown historical usage is not zero.
2. Reconcile all provider-account activity from billing evidence, including use outside this app. Record a source reference and aware UTC cutoff in the stated month. The import cutoff must precede every ledger attempt in that period; imports may not reset/overwrite an existing policy or overlap recorded attempts.
3. Verify current official provider pricing, supported endpoints/model, input/output accounting and a safe upper bound. If any of these or authority across runtimes is unclear, keep that operation absent from the catalog. In particular, a search price is not a chat-token price. This run has not accepted any real rate.
4. Prepare private JSON with exactly `global` and `tenant` objects. Required fields: `scope_id` (`all` / current tenant), `historical` and `cap` in integer micro-USD (cap <=25,000,000), `cutoff`, `reference`, `enabled` (normally false), `period` (`YYYY-MM`), `catalog`. No null/assumed historical amount is allowed. The global catalog maps allowlisted operation names to source/version and either `kind: flat, per_call` or `kind: tokens, model, input_per_million, output_per_million`. Tenant policy must also exist; it cannot substitute for the global ceiling.
5. Only with the owner's separate approval and actual evidence: `python scripts/cost_control.py --db ABSOLUTE_DATABASE_PATH --tenant local-demo configure --policy PRIVATE_POLICY_PATH --owner-authorized`. Configuration cannot reset an existing period. If a partial configuration fails, leave dispatch blocked and inspect the existing immutable rows; do not delete data to retry.
6. Stop admission immediately: `python scripts/cost_control.py --db ABSOLUTE_DATABASE_PATH stop`. This cannot retract an already admitted in-flight request. Its exposure remains held. Reauthorization of an existing reconciled policy requires a source reference, `authorize --scope global|tenant --reference OWNER_REFERENCE --owner-authorized`, and no pending/uncertain rows.
7. An uncertain attempt requires provider billing evidence, not an elapsed timeout or a UI failure. `reconcile --attempt HASHED_ATTEMPT_ID --actual-micro-usd DOCUMENTED_AMOUNT --reference BILLING_REFERENCE --owner-authorized` records operator-reconciled cost and an audit event. Preserve the original attempt/quote. An amount above its bound keeps work blocked; do not repeatedly lower the figure to reopen spending.

Policies, kills, authorizations and operator reconciliations are audited locally. A new month does not inherit authorization or an invented zero history. No public endpoint accepts balances, prices, tenant IDs, receipts or budget resets. SQLite remains loopback-only and is not hosted authentication. Live/provider/staging/production verification is outstanding; offline tests prove admission logic and zero-dispatch boundaries only.
