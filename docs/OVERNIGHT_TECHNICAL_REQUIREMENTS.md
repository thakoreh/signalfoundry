## Historical starting truth (October19)

- Next.js is the SaaS gateway; verified Clerk organization identity and Convex are the intended hosted trust/data boundaries. SQLite is an unauthenticated, loopback-only local review system. Never expose it as the SaaS backend.
- Website setup, bounded DeepSeek discovery, qualification, contact-status sorting, CSV, and explicitly requested AI introductions exist. Local provider configuration does not verify hosted configuration. Public emails remain unverified unless actual verification evidence exists.
- `backend/app/outreach.py` is a real persistent **manual local** review/conversation/outcome ledger. It neither sends nor detects mail, books meetings, nor verifies sales. `/api/outreach` reads and writes reject public previews. The hosted adapter currently returns unavailable after authentication; that guard is intentional.
- Current exact-message approval includes recipient, subject, body, optional booking link, and latest inbound identity. Edits/replies/pause invalidate approval. Manual sent snapshots retain the actual copied booking link and approval hash. Opt-outs persist by tenant, canonical company domain, and actual inbound/current recipient addresses across searches.
- AI reply generation is disabled. Initial AI introductions have count limits, not a proven total US-dollar monthly ceiling. The US$25 software-versus-all-in-with-Ads budget remains unresolved.
- Clerk, Convex, Stripe, containers, provider networking, public deployment, privacy deletion, alerts, and restoration are **not established by local tests**. Older `ARCHITECTURE.md` and `PRODUCTION_READINESS.md` provider descriptions lag current discovery/draft/local-outreach code; reconcile them against source rather than repeating stale claims.

## Definition of done

**Verified release candidate:** required implementation is complete, existing data preserved, current docs reconciled, independent findings fixed, and the exact commit passes relevant checks with reproducible evidence. Features lacking credentials/permissions remain honestly gated, with concrete owner steps. This may be achievable overnight; it is not a production launch.

**Production ready:** in addition, the approved hosted environment has actual authenticated tenant persistence, configured/licensed providers and permitted transport, enforced budget policy, real billing/policy decisions, tested operations/privacy/restore, and successful end-to-end acceptance without a demo fallback. There are no open P0 defects or unaccepted material risks. A deadline, green mocks, public URL, or successful build alone does not satisfy this definition.

**Production live:** an explicitly authorized release is deployed to the verified public origin and the actual release/health/core flow is checked there. A queued deployment or local URL is not live completion. Do not deploy by inference from this checklist.
